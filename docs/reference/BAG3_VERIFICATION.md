# BAG3 variant verification against the real OFH CPRA resources

**Question:** is the requested variant `10:119669928:C:G` (GRCh38) present in the
real Our Future Health public CPRA variant lists?

**Short answer: YES on the array list; NO on the imputed list.** The Release 14 public array CPRA CSV
contains exact `10:119669928:C:G` with `Inaccurate Call=No`. The public imputed CPRA zip does not
contain the exact CPRA. The demo still uses a *synthetic* variant manifest for full branch coverage,
including illustrative imputed evidence, and that synthetic imputed branch is not a real-resource claim.

## Method
- Sources:
  - `data/raw/our_future_health_cpra_array_variant_list_grch38_v14.csv` (Release 14 public array
    CPRA CSV, 13.5 MB).
  - `data/raw/our_future_health_cpra_imputed_variant_list_grch38-csv.zip` (~609 MB, ~159M rows).
- Helper: `scripts/verify_cpra.py` — **streams** each zip member line-by-line; the file is never
  extracted to disk. Re-run:
  ```bash
  uv run python scripts/verify_cpra.py --chrom 10 --pos 119669928 --ref C --alt G \
    data/raw/our_future_health_cpra_array_variant_list_grch38_v14.csv \
    data/raw/our_future_health_cpra_imputed_variant_list_grch38-csv.zip
  ```
- Runtime grounding: `docs/reference/variant-identifiability.csv` is the small committed artifact
  derived from these checks; `config.yaml` points `variant_identifiability_path` at it, so the pipeline
  overlays BAG3 as exact-CPRA present in the array resource and absent from the imputed resource before
  source resolution. The raw lists remain local-only and are not part of the clean snapshot.

## Findings
- **Array exact CPRA `10:119669928:C:G` present: YES.**
  The array line is `10:119669928:C:G,No`, where `No` is the `Inaccurate Call` flag.
- **Imputed exact CPRA `10:119669928:C:G` present: NO.**
  Across the whole imputed list, the only line containing the position `119669928` is
  `6:119669928:AT:A` — a **different chromosome** (chr6), i.e. a coincidental position match, not our
  variant. So there is no `10:119669928` entry at all in the imputed resource.
- **Fields the CPRA lists carry:** the array list carries `variant_id, Inaccurate Call`; the imputed
  list carries `cpra_grch38, inaccurate.annotation`. They answer *presence + ref/alt + annotation
  warning*, not per-participant genotype. Imputation **DR2 / dosage-r² and AF live in the TRE variant
  summary-statistics file**, not the public CPRA list.

## Implication for the demo (honesty)
- On *real* public CPRA-list evidence, this variant is **identifiable on the array** and **absent from
  the imputed resource**. The honest source verdict is array-confirmed / imputed-evidence unavailable.
- The synthetic `variant_manifest.csv` still carries TRE-only demo metrics (for example DR2/MAF), but
  the runtime overlays public-list availability from `variant-identifiability.csv`. For BAG3, that
  means the source decision is array-confirmed / imputed-evidence unavailable even though dummy imputed
  rows may exist in the synthetic genotype slice for branch-coverage history.
- BAG3 itself sits on chr10 (~119.65–119.68 Mb, GRCh38), so the position is anatomically plausible for
  the gene; the specific C:G allele at this position is present in the public array list and absent
  from the public imputed list.
