# Profile Summary

Profile date: 2026-06-16. Input: deterministic synthetic cohort generated by
`scripts/generate_synthetic.py` (`N=500`, 22 carrier candidates, 20 included carriers).

This is scale evidence for the MVP shape, not a claim that the synthetic cohort matches OFH production
size. The production-relevant design point remains CPRA-scoped ingest: the OFH-format path fetches one
locus by indexed pVCF/tabix rather than scanning genome-wide files.

## Commands

```bash
uv run python scripts/generate_synthetic.py
uv run python -m cProfile -o prof.out run_demo.py
```

The first process-level profile was dominated by Python imports and first-time Numba dispatcher work,
so an in-process warmed profile was also taken around `pipeline.orchestrate()` only:

```python
from pathlib import Path
import cProfile

from ofh_feasibility import io, pipeline
from ofh_feasibility.config import load_config

cfg = load_config("config.yaml")
request = io.read_request(Path(cfg.data_dir) / "variant_request.csv")
pipeline.orchestrate(cfg.model_copy(update={"results_dir": "results/profile_warmup"}), request)

prof = cProfile.Profile()
prof.enable()
pipeline.orchestrate(cfg.model_copy(update={"results_dir": "results/profile_measured"}), request)
prof.disable()
prof.dump_stats("prof_pipeline.out")
```

## Interpretation

- The genotype classification path is not the bottleneck at MVP scale after the mask-first finishing
  pass; most measured time is output/provenance/QC-control work.
- `reporting._bootstrap_af_ci` is visible because it runs 1,000 bootstrap resamples for the internal
  frequency-control view. That view is internal-only and can be tuned independently of the released
  client count.
- `pipeline.emit_audit_event` includes a `git rev-parse` subprocess and output hashing; this is
  governance evidence, not carrier classification.

## Cohort-size sweep after bounded bootstrap vectorisation (N = 1k–250k)

Reproduce: `uv run python scripts/profile_pipeline.py --sweep 1000,5000,25000,100000,250000` — the seeded
synthetic cohort is tiled to size N (vectorised; no big-axis loop), then `orchestrate` is warmed and timed.

Scaling slope (log-log fit of wall vs N): **0.51**. This is below the super-linear danger zone; fixed
costs dominate at small N and genotype/reporting work dominates at large N.

| N | wall (s) | µs/row | peak RSS (MB) |
|---|---:|---:|---:|
| 1,000 | 0.346 | 346 | 223 |
| 5,000 | 0.528 | 106 | 306 |
| 25,000 | 0.832 | 33 | 538 |
| 100,000 | 2.847 | 28 | 992 |
| 250,000 | 5.725 | 23 | 2,255 |

Top cumulative @ N=250k after the fix: `run_pipeline` 4.99 s (87%) · **`build_frequency_control`
3.31 s → `_kinship_stability` 2.97 s (52%)** · `build_candidate_table` 1.15 s (20%) ·
`assert_unique_key` 0.78 s (14%).

Previous profile for comparison: 250k wall time was **15.6 s** and `build_frequency_control` was **9.0 s**
before the bootstrap vectorisation. The follow-up therefore removes about **63%** of the 250k wall time in
this harness while leaving release semantics unchanged.

### Findings (evidence-backed)
- **Compute has no O(n²) signal.** `build_candidate_table` (3 guarded left-merges) grows roughly linearly;
  governance overhead (`git rev-parse`, provenance, audit) amortises to negligible at scale (run_pipeline
  is 87% of the total at 250k).
- **The internal AF bootstrap hot spot was reduced, not hand-waved.** `reporting._bootstrap_af_ci` still
  does 1,000 resamples for the internal-only `frequency_control_view` (never client-exported), but it now
  draws them in bounded vectorised chunks with an 8 MiB default draw cap. A regression test confirms the
  chunked vectorised path matches the prior seeded loop.
- **Memory is still the watch item on the simplified path.** Peak RSS at 250k in the final sweep was
  ~2.26 GB, extrapolating roughly to ~6.8 GB at 755k if the simplified whole-slice path were used at that
  size. This remains a demo-path measurement: it loads the whole genotype slice and carries a
  `candidate.copy()` in frequency-control. The production **`ofh_tre` path is tabix-scoped to one locus**,
  so real memory should be far leaner. Trim targets: avoid the `candidate.copy()` and keep bootstrap draw
  chunks bounded.
- **Input-integrity guards cost ~14%** (`assert_unique_key`) — a correctness feature (fan-out / silent-loss
  prevention); candidate to gate behind a debug flag at biobank scale.

**Headline:** linear scaling, no quadratic blow-up; the only measured hot spot was the internal AF
bootstrap and the bounded vectorisation follow-up is now applied and re-profiled. Memory remains a
watch-item on the *simplified* path only (the real ingest is scoped).
