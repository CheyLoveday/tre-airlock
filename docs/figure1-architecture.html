Two views of one system. Panel A is the static package structure — how the code is layered. Panel B is the dynamic process structure — how a request flows to a governed result. Both share one pure core: A shows where the logic lives, B shows when it runs.

A. Functional core / imperative shell. The pure core (QC, carrier logic, disclosure control, output builders, release predicate) holds the business logic and never touches the filesystem; the shell does all IO and chains stages; orchestration wires them into a quick path or a staged DAG. A compiled numeric kernel handles the hot carrier loop and is reconciled against a NumPy reference. Typed request/result/release objects validate the edges.

B

Process structure

one governed flow · three gates 🔒 · an epidemiology handoff

genetics governance gate 🔒 client release epidemiology handoff

B. A typed request passes a request-integrity pre-flight, per-participant QC, and carrier classification under a consent gate, then statistical disclosure control and a fail-closed airlock that emits a single client-facing aggregate. A pseudonymised carrier set is handed to epidemiology for phenotype eligibility and returned in governed aggregate form. The same core runs in-memory (quick path) or as a staged DAG (reproducible path).

Synthetic data on real-shaped formats · pure functional core · scoped, vectorised, reproducible execution · governed by construction (consent · disclosure control · fail-closed release).
